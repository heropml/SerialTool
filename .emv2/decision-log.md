# 关键决策记录

## 2026-08-23 - 下一阶段先可信度，后扩协议面

### 决策内容
先修自动应答冷却、更新完整性、Webhook 出站安全、诊断日志和发行签名；其间不新增 CAN / HID / MQTT / 插件等大能力。

### 理由
CommTool 的串口、网络、Modbus、自动化、录制和多会话已形成明显功能优势；当前短板主要是“能否信任更新、能否稳定复现、出了问题能否定位”，继续堆入口会放大维护成本。

### 影响
下一版可以定义为可信度 / 质量版，功能变化小但能明显提升发布可信度与长期维护效率。

- `docs/SCHEDULE.md`

## 2026-08-23 - 市场借鉴聚焦可交付工作流

### 决策内容
优先评估设备操作面板、工程级帧模板、会话索引 / 复现包；远程串口、被动抓串口、TLS / DTLS、CLI 仅在明确用户需求出现后立项。

### 理由
这些能力能复用现有多条发送、仪表盘、工程文件、录制回放和帧构造器，投入较小且直接改善现场交付；广铺新 transport 会增加跨平台、打包和测试矩阵。

### 影响
产品继续保持“轻量、稳定、好用”，同时从个人调试工具向可分享的设备工作流迈一步。

- IO Ninja Packet Templates / Session Linking
- Docklight receive sequences / checksum validation
- Packet Sender panel / portable / CLI documentation

## 2026-08-23 - 安全默认升级采用显式、受信迁移

### 决策内容
新增更严格安全默认时，不在归一化函数里全局兼容旧值；只对本机可信旧配置，或用户已确认保留外部动作的导入配置，补齐缺失的旧权限字段。新版明确写入的 `False` 永不被迁移覆盖。

### 理由
既要避免升级后已有 LAN / HTTP Webhook 静默停发，也不能让任意新配置或未确认导入绕过“公网 HTTPS”默认。把迁移与 normalize 分开，可清楚区分版本兼容和日常安全规则。

### 影响
旧 Webhook 行为连续，新建与显式收紧的规则保持安全；后续新增破坏性安全字段沿用同一迁移模式。
