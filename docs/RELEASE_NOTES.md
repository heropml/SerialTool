串口 + 网络一体调试工具。本版把自动化从「GUI 配置」推进到「代码级可编程」：**脚本控制台、宏录制、收发任务统一互斥**。

## 1. 脚本控制台

菜单栏「功能 → 脚本控制台」：用 **Python 脚本**驱动当前连接的真实收发，做自检、老化、批量配置、协议联调等 GUI 表格表达不了的流程。

API 为 `send / recv / expect / sleep / log / check / hexs`：`expect("OK", timeout=1000)` 等到回包才继续、超时返回 `None`；`check(条件, "说明")` 逐条记通过 / 失败并在结束时给出汇总；`hexs("01 03")` 方便手搓二进制帧。可保存多个命名脚本、下拉切换，随会话配置持久化，也能导出 JSON 分享（导入会先征求同意——脚本以本程序权限运行）。

运行期间脚本**独占收发流**，自动应答与 Modbus 主机自动暂停、结束恢复；「停止」在 `send / expect / recv / sleep` 处生效。

## 2. 宏录制

脚本控制台点「● 录制」，回主界面正常手动收发，完成后点「■ 停止录制」：你的操作会被**自动翻译成脚本**存进脚本库，可直接点「运行」重放。

每次发送生成 `send(...)`、其后回包合并成 `expect(...)` + `check(...)`（超时按实测延迟留 3 倍余量），操作间隔 ≥50ms 补 `sleep(ms)` 保留原节奏。**不会写代码也能把一段调试流程变成可重复的用例**。录制只记「用户手动发」——脚本自身发送、自动应答 / Modbus 从机回复、序列 / 定时 / 多条循环都不会混进来。

## 3. 收发任务统一互斥

脚本 / 自动化序列 / 文件传输 / 宏录制 / 定时发送 / 多条循环 / Modbus 主机之间**统一互斥**：已有任务占用收发流时，另一项启动会明确提示，而不是悄悄抢线路导致串帧、回包被错误任务消费。脚本接管时还会取消 Modbus 在途请求并隔离一个完整超时窗，避免旧响应污染脚本的第一个 `expect`。

## 4. 功能菜单分组与界面修复

「功能」菜单按主题分四组（**帧处理 / 可视化 / 自动化 / 通信传输**）并加分隔符，项目多了也一眼找得到，Modbus 主机仍在末位。另修复各对话框下拉框展开瞬间透出系统强调色的问题。
