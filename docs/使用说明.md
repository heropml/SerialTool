## 1. 快速上手

1. 从 [Releases](https://github.com/heropml/SerialTool/releases) 安装（见 [第 9 节](#9-安装与系统要求)），桌面双击 **CommTool** 图标启动
2. 左侧「连接设置」里选**类型**（串口 / RTT / 网络 / Virtual / BLE）→ 填参数 → 点 **打开串口 / 连接 / 打开 / 开始监听 / 启动虚拟连接**
3. 右侧「数据区」实时显示收发内容，下方「发送区」输入要发送的数据
4. 需要同窗多连接时用「新建会话」开多标签（串口 / RTT / TCP / UDP / Virtual / BLE 可并发）

空白终端顶部提供“快速开始”：可直接启动 Virtual 回环、打开内置示例或继续最近工程。帧构造器可保存个人帧模板；录制回放会索引最近保存/打开的 `.ctrec`。遇到问题可用“帮助 → 导出诊断包”生成脱敏支持包。Webhook 默认只允许公网 HTTPS；仅在目标确为可信局域网服务时开启 LAN / HTTP 例外。

## ⭐ CommTool v1.9.0 RTT 与 Linux 升级修复

- **RTT 断开** — 断开后界面可以继续操作。驱动在后台清理，完成后才释放当前探针。旧连接排队的状态和错误提示不会影响新连接。
- **Linux 覆盖升级** — 安装器先检查并暂存新版文件。失败时尝试恢复旧程序、运行库与启动入口，并保留用户配置。若有文件无法恢复，安装器会提示备份位置。

## ⭐ CommTool v1.8.9 多探针 RTT

- **同窗口多路 RTT** — 在不同标签分别选择不同的 J-Link，同型号的两块目标也可同时连接。重新展开调试器下拉框会刷新列表。
- **缺少下行缓冲区时保留连接** — 所选通道无法发送时，CommTool 会提示检查通道。

## ⭐ CommTool v1.8.8 串口计时、终端输入与实时日志

- 终端模式逐键发送，发送框显示当前正在输入的命令。按回车或点「发送」会发出配置的行结束符并清空预览。退格和光标编辑会更新本地回显，中文输入法确认的文字也会发送。
- 同开串口和 RTT 时，每个标签分别记录自己的 HEX 或终端文本。打开「实时记录」即可选文件；记录中手动断开，再次连上会提示选择新文件。握手期间已手动选定的文件会继续使用。
- 串口日志、显示和录制沿用后台读取时间。RX 状态栏给出读取块数，启用时间分包或协议组帧后也会显示对应计数。悬停可查看字节速率和块速率。20 ms 边界取决于相邻读取的间隔。

## ⭐ CommTool v1.8.7 串口后端与更新证书

- 串口默认使用独立线程中的 QSerialPort 后端，主窗口和串口桥接共用连接接口。启动前设置 `COMMTOOL_SERIAL_BACKEND=pyserial` 可切换后端进行对照。
- 20ms 静默组帧使用读取时间戳。Parity / Framing / Break 线路错误和可选控制线不支持的情况允许数据连接继续使用。
- macOS 的 Mark / Space，以及 POSIX 的 1.5 停止位会明确拒绝。在线参数被驱动拒绝且成功回滚时，会提示原因并恢复控件。回滚失败会清理连接和线程。
- 发送返回 Qt 接受入队的字节数，输出积压上限为 4MiB。写失败会清空输出并关闭连接。
- 更新检查在系统默认信任库基础上补充 certifi 根证书，修复部分打包环境的证书验证失败。
- **记住实时记录目录** — 保存窗口沿用当前配置档上次成功记录的目录，并按当前时间建议新文件名。

## ⭐ CommTool v1.8.6 串口分帧精度优化

- 串口后台等待首字节，合并驱动缓冲区中已到达的尾部数据，以整块读取完成时刻记录时间戳。
- 时间分包显示与自动应答静默组帧使用接收线程时间戳，界面排队时仍按实际接收间隔判断。常用静默时间可设为 20ms。
- 补读期间提前登记接收活动，避免上一帧提前结束；补读失败仍交付已读取的数据，关闭连接时取消阻塞读取。
- 自动应答静默组帧每会话最多缓存 1MiB，超限提示并丢弃整帧，静默间隔后恢复匹配。时间分包仅控制显示，自动应答须单独设置规则静默时间，gap=0 按接收块即时匹配。

更早的版本记录见 [GitHub Releases](https://github.com/heropml/SerialTool/releases)。

## 5. 主要功能

### 5.1 连接设置

左上角 **「连接设置」** 卡片，第一行是 **「类型」** 下拉，Windows 共 8 个选项（macOS/Linux 无 BLE 时为 7 个；新装默认 **Serial 串口**）：

| 类型 | 说明 |
|------|------|
| **Serial** | 串口（COM 口）收发 |
| **RTT** | SEGGER J-Link Real-Time Transfer |
| **UDP** | 普通 UDP 收发 |
| **UDP Multicast** | UDP 组播 |
| **TCP Server** | 作为 TCP 服务端监听 |
| **TCP Client** | 作为 TCP 客户端连接 |
| **Virtual** | 虚拟连接（无硬件；可回环；用于验证与 `.ctrec` 回放） |
| **BLE** | Windows 蓝牙低功耗主机（UART 风格 Notify/Write；经典 SPP 仍走 Serial） |

卡片里的字段会**随类型动态显隐**：

- **Serial（串口）**
  - **端口**（下拉本机串口，旁边 **⟳** 手动刷新；后台也会定时扫描热插拔）
  - **波特率**（可编辑下拉，常用 1200~2000000）
  - **数据位**（5 / 6 / 7 / 8，默认 8）、**校验位**（None / Even / Odd / Mark / Space）、**停止位**（1 / 1.5 / 2）
  - 点 **「打开串口」** 连接
- **UDP**
  - **本地IP**（下拉，列出本机网卡 IP，`0.0.0.0` = 所有网卡）
  - **本地端口**
  - **指定远程** 开关 — **关** = 回复最近发来数据的对端；**开** = 启用下面的 **远程IP / 远程端口**，固定发往该地址
    - **关**模式下每收到一包数据，会把灰显的「远程IP / 远程端口」自动刷成**最近发来方的地址**（让你看到当前在跟谁通信、发送会回复给谁；对端变化才刷）。收到某方的包后想固定回它，直接打开「指定远程」即预填好该地址
- **UDP Multicast（组播）**
  - **本地IP**（出 / 入网卡，`0.0.0.0` = 默认）
  - **组播地址**（如 `239.0.0.1`，须在 `224.0.0.0 ~ 239.255.255.255` 范围内）
  - **本地端口**
- **TCP Server**
  - **本地IP**、**本地端口** → 点 **「开始监听」**
  - 有客户端连入后出现 **「目标」** 下拉，可选某个客户端或 **「全部」**（广播）来发送
- **TCP Client**
  - **远程IP**（必填）、**远程端口**（必填）→ 点 **「连接」**
- **Virtual（虚拟）**
  - 可不接硬件直接启动；可选 **回环**
  - 用于验证自动应答 / 脚本 / 序列，以及会话录制回放时的注入落点
- **RTT（SEGGER J-Link）**
  - 选择 **器件**、**调试器**（自动或序列号）、**接口**（SWD/JTAG）、速度（kHz）和通道。自动会优先使用上次成功的探针；显式序列号绝不自动改选其他探针。
  - 同时使用多把探针时，每个 RTT 标签选择不同的调试器序列号。通道号由各块板的固件决定，两块板的命令终端都配置在通道 0 时，两个标签都选 0。识别到实际序列号后，自动重连会沿用同一把探针。缺少下行缓冲区的通道仍可接收数据。
  - 器件旁的 **「…」** 打开完整 J-Link 目录，支持筛选、排序和回填；侧栏故意只保留常用快捷项，仍可自由输入器件名。
  - **RTT 地址**支持自动、精确地址，以及 `起点+范围` / `起点..结束` 的 RAM 搜索；**连接时复位**为可选项。
  - 需安装 SEGGER J-Link 驱动。J-Link 已启动 RTT、但固件控制块尚未出现时会显示等待提示，而非断开。
- **BLE（Windows）**
  - 点 **扫描** 会弹出窗口，列出名称 / 地址 / 广播 **UUID** / RSSI（含信号条）/ **TX** / **可连接** / **观测间隔（估算）** / **厂商**（按地址去重）。该间隔是本机两次收到扫描回调的平滑时间差（受 Windows / Bleak 批处理、扫描响应、丢包影响），**不是**设备广播包里的真实 Advertising Interval，不能用来判断外设广播周期。**过滤**打开后可勾选规则（默认隐藏无名空包；还可只要有名称 / 可连接 / UUID / 厂商数据、隐藏过期、只要用过）；关掉则全部显示。可打开 **RSSI 过滤**，用 −100～−30 dBm 滑条隐藏弱信号。选中一行看底部广播明细（类型、Flags、外观名、厂商名、广播服务个数、上次连接时间、服务数据、可复制 RAW）。一段时间无广播的行会变灰。可按名称 / 地址 / UUID / 厂商搜索。双击或点 **使用此设备** 填回侧栏
  - 再选 **模板**（FFF0 / FFE0 / Nordic UART / Microchip UART / Custom）+ 可编辑的服务 / **写入（PC→设备）** / **通知（设备→PC）** UUID，方向反了可 **对调**。**写入方式** 默认自动（按特征属性选 Write 或 Write Without Response）
  - 点 **「连接」**；连接中显示「连接中…」，按钮为断开（可取消）。状态栏显示名称 + 地址 + **MTU**
  - 连上后走现有收发管线（文本/HEX、日志、`.ctrec`、自动应答、序列、脚本、组帧）。**无 PCAP**（不是网卡抓包）；macOS / Linux 上此类型会提示不支持
  - 同一设备不能被两个会话同时打开；自动重连按已保存的地址 + UUID，不再扫描，最多 10 次（与串口相同）

**动作按钮**文案随协议 + 状态变化：

| 类型 | 按钮 |
|------|------|
| Serial | 打开串口 / 关闭串口 |
| RTT | 连接 / 断开 |
| UDP / UDP Multicast | 打开 / 关闭 |
| TCP Server | 开始监听 / 停止监听 |
| TCP Client | 连接 / 断开 |
| Virtual | 启动虚拟连接 / 停止虚拟连接 |
| BLE | 连接 / 断开 |

连接建立后整张卡片**锁定变灰**；被禁用的输入框也会变灰。

### 5.2 数据接收

收发同框显示，箭头区分方向：

| 标记 | 含义 |
|------|------|
| `← 收` | 接收到的数据 |
| `→ 发` | 发送出去的数据 |

**滚动锁定 / 自动跟随**

- 往上翻历史时视图**定住不动**，新数据照常在后台接收、不丢
- 右下角浮出 **「↓ 最新」** 按钮，点一下回到底部并恢复自动跟随

**单击行高亮**

- 单击数据区任意一行**高亮该行**，再点一次取消，方便盯住关心的那一帧

**显示选项**（数据区卡片）

- **显示方式** — 文本 / HEX / HEX 转储 / 数值（互斥）；收发一致，与「HEX 发送」无关。转储可选行宽；数值可选类型与字节序
- **自动换行** — 行超长自动折行，关闭后右侧滚动条
- **字符编码** — 选 自动 / UTF-8 / GBK / GB2312 / GB18030 / Big5 / ASCII / Latin-1 共 8 项；影响 RX 解码 / TX 文本编码 / 文件加载
- **显示时间戳** — 每个新块前加 `[2026/06/03 09:48:54 023]`，同时显示 ← / → 方向箭头
- **时间分包** + **超时 ms** — 两次接收间隔超过设定毫秒就开新行（默认 20ms，适合 Modbus）
- **换行分包** + **换行符模式** — 按 `\r\n` / `\r` / `\n` 切行
  - **自动**：三种风格全识别（Windows + Linux + Mac 兼容）
  - **CRLF / LF / CR**：只认指定换行符，严格模式
- **实时记录** — Xshell 风格连续日志写到 `.log` 文件，**显示什么写什么**（带时间戳、箭头、HEX/ASCII）
  - **按大小分包（v1.0.2）** — 开关旁的下拉可选 不分包 / 1M / 2M / 5M / 10M / 20M / 50M / 100M，也可手填自定义（如 `3M`、`500K`）；写满设定大小自动切到新文件（原名加 `_001` / `_002`…）
  - 当前日志文件路径会显示在**底部状态栏右侧**（详见 [7 状态栏](#7-状态栏)）
- **最大行数** — 显示行上限，超出自动丢弃最旧的（防止长跑卡顿）；**不影响日志文件**
- **只显高亮行** — 打开后只保留命中关键字的行，其余隐藏（配合「关键字高亮」用，详见 [5.4](#54-关键字高亮)）

**字号** — 右上角 `A−` `A+` 微调（7~28pt），适配大屏 / 小屏

**保存 / 清空** — 卡片底部按钮，保存到 `save_log_YYYYMMDD_HHMMSS.log`

**协议帧解析**（标题栏「功能 → 帧解析」）— 默认每个收包当一帧。串口/TCP 粘包、拆包时勾选 **协议帧模式**，按帧头+长度字段组完整帧后再解析（波形 HEX / 仪表盘 HEX / 结构化记录共用）。UDP 默认一数据报一帧。显示区与 `.ctrec` 仍是原始收包。对话框底部有解析计数；「没有字段」时可看最近失败原因。

### 5.3 数据发送

- **HEX 发送** — 输入的 16 进制字符串按字节发送，下面写法都识别：

| 写法 | 解析 |
|------|------|
| `AA BB CC DD` | 4 字节 |
| `AABBCCDD` | 4 字节 |
| `AA-BB-CC-DD` | 4 字节 |
| `AA:BB:CC:DD` | 4 字节 |
| `0xAA 0xBB 0xCC` | 3 字节 |
| `// 注释\nAA BB` | 2 字节 |
| `/* 段注释 */ AA BB` | 2 字节 |

  非法字符（如 `AA ZZ BB`）会拒绝发送并提示格式错误。

- **Ctrl+Enter 发送** — 普通发送框 Ctrl+Enter 发送，Enter 仍换行（终端模式不变，Enter 透传）
- **追加换行** + **换行符模式（CRLF / LF / CR）** — 每次发送自动追加换行符（AT 命令场景常用）
- **定时发送** + **周期 ms** — 周期性自动发送当前内容，最小 10ms；发送失败时（未连接 / 数据格式错误 / 无目标等）自动停止
- **校验**（9 种算法 +「无」）— 发送前在末尾追加校验字节

| 算法 | 字节 | 用途 |
|------|------|------|
| 无 | 0 | 不追加 |
| 和校验 / ADD8 | 1 | 简单累加和 |
| 累加和取反 / ~ADD8 | 1 | 累加和按位取反 |
| 异或 / XOR8 | 1 | 全字节异或 |
| CRC8 | 1 | 多项式 0x07（标准 CCITT）|
| **MOBUS** | 1 | **CRC8 多项式 0x31**，国内嵌入式常用 |
| ModbusCRC16 | 2 | Modbus RTU 标准，小端 |
| CCITT-CRC16 | 2 | CRC-16/CCITT-FALSE，大端 |
| CRC32 | 4 | Ethernet / ZIP 标准 |
| ADD16 | 2 | 16 位累加和 |

**读取文件** — 直接把文件内容塞进发送框（HEX 模式自动转 hex 字符串）

**多条发送** — 发送区「多条发送」按钮，多行数据批量管理，详见 [5.5](#55-多条发送)

**快捷栏（v1.0.2）** — 发送区上方一行直接平铺当前分组里的每条命令为按钮，点一下即发，无需打开弹窗，详见 [5.5](#55-多条发送)

### 5.4 关键字高亮

数据区标题栏 **「关键字高亮」** 按钮打开弹窗，给数据区里命中的关键字上色，一眼定位关心的字段：

- **多条关键字**，每条**独立颜色**
- 着色方式可选 **背景** 或 **文字**
- 可限定范围：**收 / 发 / 收发**
- **区分大小写**子串匹配；自动跳过时间戳，不会误高亮
- 规则**持久化**，下次启动保留

**分组 / 规则集（v1.0.2）**

- 弹窗左侧是**分组列表**，可 **新建** / **双击重命名** / **删除** 分组，把不同场景的关键字归到各自分组
- 数据区标题栏新增**分组下拉**，选哪个分组生效；含 **「（关闭）」** 项可一键停用全部高亮
- 正在弹窗里**编辑的分组**与当前**生效的分组**相互独立，改这个不影响那个

## 6. 实用技巧

- **Modbus 调试**：显示方式选 HEX + HEX 发送 + 时间分包（20ms）+ ModbusCRC16
- **AT 命令调试**：显示方式选文本 + 追加 CRLF + 换行分包（自动）
- **长跑监控**：开实时记录 → 日志文件可后续 Notepad++ / VS Code 打开分析
- **HEX 写注释**：HEX 发送框可写 `// 行注释`、`/* 段注释 */`、`# 行注释`，提交时自动去除
- **拖动布局**：左右 / 上下分割条都可以拖，调成顺手的比例后下次启动保留
- **盯关键帧**：给关键字配高亮 + 开「只显高亮行」，刷屏里也能只盯命中的行；翻历史时滚动锁定不怕被新数据冲走
- **批量指令**：常用的几条指令丢进「多条发送」勾上循环，按每行延时轮发，省得一条条手敲
- **快捷直发**：把常用命令归到一个分组，发送区上方快捷栏一键平铺成按钮，点哪条发哪条，不用开弹窗
- **分场景高亮**：不同协议 / 模块各建一个高亮分组，用数据区的分组下拉随时切换，调试别的设备时选「（关闭）」即可
- **长跑切包**：实时记录选个分包大小（如 10M），日志写满自动切新文件，状态栏随时能看到当前写到哪个文件

## 8. 常见问题

**Q：TCP Server 开始监听失败 / 端口被占用？**
A：该端口被其他程序占用，或需要权限；换个端口或关掉占用程序再试。

**Q：TCP Client 连不上？**
A：检查远程 IP / 端口是否正确、对端是否在监听、防火墙是否放行。

**Q：UDP 点发送提示"无可发送目标"？**
A：没开"指定远程"且还没收到过任何对端数据。开启"指定远程"填好远程地址，或等对端先发一包。

**Q：UDP 组播收不到数据？**
A：确认防火墙放行、收发在同一组播地址和端口、在同一网段 / 网卡。

**Q：RTT 找不到 J-Link 或控制块？**
A：先安装官方 SEGGER J-Link 驱动，再核对探针、接口、器件名和速度。「等待控制块」表示探针已连上、但固件尚未初始化 RTT；检查固件 RTT 初始化，或按目标提供的地址/范围填写。

**Q：定时发送不工作？**
A：周期最小 10ms，且必须保持连接；断开时定时会自动暂停。

**Q：中文显示乱码？**
A：自动模式默认 UTF-8 优先，乱码会自动回退 GBK。如果还是不对，设备可能用其他编码（如 Big5），在"字符编码"下拉里明确指定，或把显示方式切到 HEX / HEX 转储看原始字节。

**Q：HEX 发送报"长度必须为偶数"？**
A：HEX 是按字节解析的，`AA B` 是 3 个 hex 字符无法配对，补成 `AA 0B` 或 `AAB0` 即可。

**Q：日志文件大了会卡吗？**
A：写入是追加模式，几十 MB / 几百 MB 都不会卡。"最大行数"限制只影响**界面显示**的行数，不影响日志写入。

**Q：往上翻历史时新数据会丢吗？**
A：不会。滚动锁定只是把视图定住，数据照常在后台接收。点右下角「↓ 最新」回到底部即可继续自动跟随。

**Q：开了「只显高亮行」却什么都没显示？**
A：说明当前没有命中的行。先在「关键字高亮」里配好关键字，且范围（收 / 发 / 收发）要匹配，命中的行才会留下。

## 9. 安装与系统要求

在 [GitHub Release](https://github.com/heropml/SerialTool/releases/tag/comm-v1.9.0) 下载 v1.9.0 安装包，镜像附件见 [Gitee Release](https://gitee.com/heropml/SerialTool/releases/tag/comm-v1.9.0)。

### Windows

- 系统：Windows 10 / 11（64 位）
- 推荐：`CommTool_Setup_v1.9.0.exe` — 向导安装，可选桌面快捷方式；当前用户安装无需管理员

### macOS

- 仅 **Apple Silicon**（arm64）：从 `comm-v1.9.0` 下载 `CommTool_v1.9.0.dmg`
- 打开 DMG，把 CommTool 拖进「应用程序」
- 若提示「已损坏，无法打开」（未公证），在终端执行一次：

```bash
xattr -dr com.apple.quarantine /Applications/CommTool.app
```

### Linux

- **x86_64**，glibc ≥ 2.27（Ubuntu 18.04+ / 多数麒麟）。xcb / X11 已打进包，一般不必再 `apt`
- 文件：`CommTool_Setup_v1.9.0_linux_x86_64.run`

```bash
chmod +x CommTool_Setup_v<version>_linux_x86_64.run
./CommTool_Setup_v<version>_linux_x86_64.run
```

- 默认装到 `~/.local/opt/CommTool`（**无需 sudo**），并写入应用菜单与桌面图标
- 启动：应用菜单 / 桌面图标，或 `~/.local/opt/CommTool/CommTool`（若 `~/.local/bin` 在 PATH 里也可直接 `CommTool`）
- 卸载：`~/.local/opt/CommTool/uninstall.sh`
- 串口列表为空：把当前用户加入 `dialout` 组后重新登录：`sudo usermod -aG dialout $USER`

磁盘约 100–200 MB。

使用 RTT 还需安装官方 SEGGER J-Link 驱动；应用已随包带上 Python 封装。
