## 1. 快速上手

1. 桌面双击 **CommTool** 图标启动
2. 左侧「连接设置」里选**类型**（串口 / 网络 / Virtual）→ 填参数 → 点 **打开串口 / 打开 / 连接 / 开始监听 / 启动虚拟连接**
3. 右侧「数据区」实时显示收发内容，下方「发送区」输入要发送的数据
4. 需要同窗多连接时用「新建会话」开多标签（串口 / TCP / UDP / Virtual 可并发）

## ⭐ CommTool v1.5.0 终端多会话标签

本版为 **v1.5.0**：同一窗口内可并发多个独立连接（串口 / TCP / UDP / 虚拟），标签即会话：

- **按会话隔离**：连接、收发区、与该页相关的显示选项、实时日志路径、自动重连、**定时发送**均属当前标签。后台标签可继续收数、写日志、定时发。
- **窗口级能力**：自动应答 / Modbus 从机配置与收包处理由整窗共享，只作用于当前活动标签。脚本控制台、自动化序列、文件传输、Modbus 主机、录制/回放、发送 DSL、设备扫描、以及多条发送的**循环发送**共用整窗占用表。互斥提示会列出具体占用任务；脚本/序列/传输/Modbus 等独占任务运行时不可切走该会话。
- **多条循环发送**：循环定时器是窗口级的，切标签时会**自动停止循环**并提示（不迁移到新标签）；与每会话独立、切走仍继续的定时发送不同。
- **标签状态**：绿点=已连接，黄点=重连等待，灰点=未连接；悬停可看连接 / 定时发送 / 实时日志。双击标签可自定义名称（tooltip 仍显示真实端口/地址）。
- **关键字高亮**：每条可选文本 / 正则 / HEX（与查找栏同一套安全解析）。
- **草稿自动保存**：连接/发送等用户编辑约 1.5 秒防抖落盘；定时发送不会触发写盘。
- **多窗口 / 配置档**：帮助 → 新建窗口（或另一份 profile）仍是独立工作台；多会话是窗内并发，不替代多窗 profile。
- **边界**：本版不做会话树、拖拽分屏、标签拖出成窗；两会话不可共用同一展开后的日志路径。

## ★ CommTool v1.3.7 连接预设 / 数据驱动序列 / JUnit 报告 / 统计诊断 / Modbus 专业化 / 回放分析

本版围绕「连接可复用、用例可批量、结果可交付」，并把 Modbus 模拟与记录回放做深：

- **具名连接预设** — 连接栏新增预设下拉与「保存 / 管理」：串口或网络的全部参数、备注和自动重连策略可存成具名预设，支持最近使用排序、复制、删除和 JSON 导入导出，并随 `.ctproj` 工程打包。已连接时应用预设会被拒绝并回退占位项，避免连接中被改参数。
- **序列变量与上下文** — 序列的「发送」「期望回包」支持 `${name}` 模板；每步可从回包按文本、HEX、正则分组或 Modbus 字段提取变量，供后续步骤使用，变量作用域按单轮隔离，`$${` 转义为字面 `${`。未定义变量不再静默降级成纯发送，而是当步失败，避免循环老化出现假通过。
- **CSV 数据驱动序列** — 序列可绑定 CSV 数据集：每行参数跑一轮，表头作为 `${var}` 种子，轮数取行数；报告关联 CSV 行号与设备标识（取 `device_id` / `sn` / `name` 等列）。CSV 依次按 utf-8、GBK（Excel 另存）、latin-1 回退解码。
- **测试报告新增 JUnit XML** — 「导出报告」可选 HTML / CSV / **JUnit XML**，后者可直接被 Jenkins、GitLab CI 收集。三种格式统一补充软件版本、开始与结束时间、测试参数（轮数、步骤数、失败即停）和 CSV 路径，每步记录耗时、失败原因与关键收发帧（TX / RX HEX）。**行为变更：中途停止或断连也会出汇总并可导出**（报告标记为已停止），不再丢弃残缺结果；多轮运行会逐轮展开每一步明细。
- **收发统计与诊断增强** — 状态栏 RX/TX 增加包速率（pkt/s，「包」指底层收发块而非协议帧）；悬浮提示补充峰值包速、包大小 min/avg/max、大小分布直方图、序列 / Modbus 主机 / 连接三类超时次数以及近 1 分钟均速。波形图可订阅 `rx_Bps`、`tx_Bps`、`rx_pps`、`tx_pps` 四个吞吐通道；状态栏右键或工作区「I/O Graph」可一键打开时间轴预设。统计可一键重置，不影响记录与数据区。无新依赖。
- **示例工程** — 提供 Modbus RTU、AT 调制解调器、双会话预设等 .ctproj；源码位于 `examples/`，Windows 安装目录会包含 `examples`，macOS DMG 内提供可见的 `Examples` 文件夹。用「工程 → 打开」加载；双会话标签为运行时态，打开后新建会话并应用 Session B 连接预设。

- **多从机模拟** — 自动应答的 Modbus 从机可以在同一条总线上模拟多个从机：「多从机行表」（地址 / Server ID / Extra JSON）一行一个从机，各自给寄存器表和从机 ID，没写的项按上方的单从机配置继承，**填了行表就以它为准、覆盖上面的单地址表**。TCP Server 下每个客户端仍各自维护半包缓冲，互不串帧；广播地址 0 只接受写功能码，读以及 FC08 / FC11 / FC17 / FC23 会被拒绝并在结果列提示「广播地址仅支持写操作」。
- **异常码注入与动态寄存器** — 从机可以按策略返回异常码，用来验证主机的异常处理分支；寄存器值可以按递增、递减、随机、正弦、斜坡自动变化，模拟真实设备的运行状态，主机写进去的值会覆盖动态值直到会话重置。界面上目前只有「异常码」和「注入异常」开关，**注入模式、功能码与地址过滤、动态寄存器规则暂时没有界面，需要写在工程文件里**：`{"exception": {"enabled": true, "code": 4, "mode": "n", "n": 3, "funcs": [3, 6], "addrs": [10, 11]}, "dynamics": [{"space": "holding", "addr": 0, "mode": "sine", "min": 0, "max": 100, "period_ms": 2000}]}`。异常 `mode` 取 `always` / `once` / `n`（每 N 次发一次），`funcs` 和 `addrs` 留空表示不限；动态 `space` 取 `holding` / `input` / `coils` / `discrete`，`mode` 取 `inc` / `dec` / `random` / `sine` / `ramp`（另有 `step` / `phase` / `seed`），`min` 等于 `max` 时退化为常量。给 `random` 配 `seed` 后序列可复现，会话重置会回到序列开头。
- **补齐常用功能码** — 功能码下拉新增 **08 诊断(回显)**、**11 通信事件计数**、**17 报告从机 ID**、**23 读写多寄存器**，主机与从机两侧都实现。FC23 在数量列按 `读数量 @ 写地址 : 写入值` 填（写入值空格分隔，如 `2 @ 100 : 10 20`）；FC08 的诊断数据填同一列，结果会同时给出十进制与十六进制，便于和发出去的值逐位对照，**子功能暂时没有界面**，需要在工程文件的轮询规则里写 `diag_sub`（缺省 0 = 回环）。FC17 的从机 ID 长度未标准化，响应是变长的：RTU 按字节数字段取帧、Modbus-TCP 按 MBAP 长度字段、ASCII 按帧尾定界，三种变体都能完整收帧。
- **图表持久化与结构化回放** — 波形图和仪表盘的数据源、单位与布局随 `.ctproj` 工程保存，重开工程即恢复。结构化记录可以按原时间轴回放并驱动同一套图表，支持暂停、单步、倍速与进度定位；`.ctrec` 字节级回放同样支持暂停、单步和按秒定位，单步会自动先暂停，保证每点一次只前进一个事件。
- **会话差异筛选与导出** — 会话比较结果可以按方向（RX / TX）和时间差绝对值筛选，汇总计数跟着当前筛选结果走；筛选后的行可导出 CSV 或 JSONL，筛到一行不剩时导出按钮会自动禁用，不会产出只有表头的空文件。

## ★ CommTool v1.2.1 Modbus 主机增强

在 v1.2.0「Modbus 主机轮询」基础上补齐写多功能码、加固误操作安全、表格可拖列——经六轮对抗式评审收敛：

- **写多功能码** — 主机写补上 **0F 写多线圈 / 10 写多寄存器**：在「数量/写值」格填多个值（逗号或空格分隔，如 `100,200,300`；0F 线圈填 0/1），数量由值个数决定。

## ★ CommTool v1.2.0 Modbus 主机轮询

继自动应答的 Modbus RTU **从机**之后，新增 **主机（master / 轮询）**：把本工具当 Modbus 主机，按每行周期轮询从机寄存器 / 线圈并实时显示结果——主机联调、查表、巡检不用再手敲请求帧：

- **Modbus 主机** — 数据区标题栏点「Modbus 主机」，每行配 `名称 / 从机ID / 功能码 / 起始地址 / 数量(读)或写值(写) / 周期ms` → 实时 **值（十进制 + 十六进制）** + **状态**。读 `01` 线圈 / `02` 离散输入 / `03` 保持 / `04` 输入寄存器；写 `05` 单线圈 / `06` 单寄存器（周期到点重复写、显示回显）。
- **半双工** — 一次只在途一条请求，收响应或超时（1s）后再发下一条；每行按各自周期独立调度。状态：**OK / 超时 / 异常（从机异常码）/ 响应无效 / 发送失败**。

- **本地回显** — 串口适配器会回显发出帧（RS-485 半双工常见）时勾选：先剥掉一份与请求相同的回显（容忍前导噪声 / 残留）再解析真实响应。尤其写 `05/06` 的回显与「写成功」同形，不开会把回显当成功、丢掉从机异常。
- **稳健核对** — 校验从机ID / 返回数量 / 写回显 / 异常功能码匹配；RTU 坏帧丢 1 字节重同步（不清整缓冲），TCP 按 MBAP 自分帧。新增 `src/modbus_master.py` + 对话框 + `tests/test_modbus_master.py`（34 项）；三语 i18n；无新依赖；启用前不影响原有行为；经三轮对抗式评审收敛。

## ★ CommTool v1.1.8 自动应答位掩码与字段匹配

## ★ CommTool v1.1.6 自动应答多步状态机

自动应答新增**多步状态机**，把多条规则串成按帧序列推进的握手 / 会话：

## ★ CommTool v1.1.5 自动应答五项增强

自动应答从"能用"推到"好用 + 可压测"：

## 5. 主要功能

### 5.1 连接设置

左上角 **「连接设置」** 卡片，第一行是 **「类型」** 下拉，共 6 个选项（新装默认 **Serial 串口**）：

| 类型 | 说明 |
|------|------|
| **Serial** | 串口（COM 口）收发 |
| **UDP** | 普通 UDP 收发 |
| **UDP Multicast** | UDP 组播 |
| **TCP Server** | 作为 TCP 服务端监听 |
| **TCP Client** | 作为 TCP 客户端连接 |
| **Virtual** | 虚拟连接（无硬件；可回环；用于验证与 `.ctrec` 回放） |

卡片里的字段会**随类型动态显隐**：

- **Serial（串口）**
  - **端口**（下拉本机串口，旁边 **⟳** 手动刷新；后台也会定时扫描热插拔）
  - **波特率**（可编辑下拉，常用 1200~2000000）
  - **数据位**（5 / 6 / 7 / 8，默认 8）、**校验位**（None / Even / Odd / Mark / Space）、**停止位**（1 / 1.5 / 2）
  - 点 **「打开串口」** 连接
- **UDP**
  - **本地IP**（下拉，列出本机网卡 IP，`0.0.0.0` = 所有网卡）
  - **本地端口**
  - **指定远程** 开关 — **关** = 回复最近发来数据的对端；**开** = 启用下面的 **远程IP / 远程端口**，固定发往该地址
    - **关**模式下每收到一包数据，会把灰显的「远程IP / 远程端口」自动刷成**最近发来方的地址**（让你看到当前在跟谁通信、发送会回复给谁；对端变化才刷）。收到某方的包后想固定回它，直接打开「指定远程」即预填好该地址
- **UDP Multicast（组播）**
  - **本地IP**（出 / 入网卡，`0.0.0.0` = 默认）
  - **组播地址**（如 `239.0.0.1`，须在 `224.0.0.0 ~ 239.255.255.255` 范围内）
  - **本地端口**
- **TCP Server**
  - **本地IP**、**本地端口** → 点 **「开始监听」**
  - 有客户端连入后出现 **「目标」** 下拉，可选某个客户端或 **「全部」**（广播）来发送
- **TCP Client**
  - **远程IP**（必填）、**远程端口**（必填）→ 点 **「连接」**
- **Virtual（虚拟）**
  - 可不接硬件直接启动；可选 **回环**
  - 用于验证自动应答 / 脚本 / 序列，以及会话录制回放时的注入落点

**动作按钮**文案随协议 + 状态变化：

| 类型 | 按钮 |
|------|------|
| Serial | 打开串口 / 关闭串口 |
| UDP / UDP Multicast | 打开 / 关闭 |
| TCP Server | 开始监听 / 停止监听 |
| TCP Client | 连接 / 断开 |
| Virtual | 启动虚拟连接 / 停止虚拟连接 |

连接建立后整张卡片**锁定变灰**；被禁用的输入框也会变灰。

### 5.2 数据接收

收发同框显示，箭头区分方向：

| 标记 | 含义 |
|------|------|
| `← 收` | 接收到的数据 |
| `→ 发` | 发送出去的数据 |

**滚动锁定 / 自动跟随**

- 往上翻历史时视图**定住不动**，新数据照常在后台接收、不丢
- 右下角浮出 **「↓ 最新」** 按钮，点一下回到底部并恢复自动跟随

**单击行高亮**

- 单击数据区任意一行**高亮该行**，再点一次取消，方便盯住关心的那一帧

**显示选项**（数据区卡片）

- **显示方式** — 文本 / HEX / HEX 转储 / 数值（互斥）；收发一致，与「HEX 发送」无关。转储可选行宽；数值可选类型与字节序
- **自动换行** — 行超长自动折行，关闭后右侧滚动条
- **字符编码** — 选 自动 / UTF-8 / GBK / GB2312 / GB18030 / Big5 / ASCII / Latin-1 共 8 项；影响 RX 解码 / TX 文本编码 / 文件加载
- **显示时间戳** — 每个新块前加 `[2026/06/03 09:48:54 023]`，同时显示 ← / → 方向箭头
- **时间分包** + **超时 ms** — 两次接收间隔超过设定毫秒就开新行（默认 20ms，适合 Modbus）
- **换行分包** + **换行符模式** — 按 `\r\n` / `\r` / `\n` 切行
  - **自动**：三种风格全识别（Windows + Linux + Mac 兼容）
  - **CRLF / LF / CR**：只认指定换行符，严格模式
- **实时记录** — Xshell 风格连续日志写到 `.log` 文件，**显示什么写什么**（带时间戳、箭头、HEX/ASCII）
  - **按大小分包（v1.0.2）** — 开关旁的下拉可选 不分包 / 1M / 2M / 5M / 10M / 20M / 50M / 100M，也可手填自定义（如 `3M`、`500K`）；写满设定大小自动切到新文件（原名加 `_001` / `_002`…）
  - 当前日志文件路径会显示在**底部状态栏右侧**（详见 [7 状态栏](#7-状态栏)）
- **最大行数** — 显示行上限，超出自动丢弃最旧的（防止长跑卡顿）；**不影响日志文件**
- **只显高亮行** — 打开后只保留命中关键字的行，其余隐藏（配合「关键字高亮」用，详见 [5.4](#54-关键字高亮)）

**字号** — 右上角 `A−` `A+` 微调（7~28pt），适配大屏 / 小屏

**保存 / 清空** — 卡片底部按钮，保存到 `save_log_YYYYMMDD_HHMMSS.log`

### 5.3 数据发送

- **HEX 发送** — 输入的 16 进制字符串按字节发送，下面写法都识别：

| 写法 | 解析 |
|------|------|
| `AA BB CC DD` | 4 字节 |
| `AABBCCDD` | 4 字节 |
| `AA-BB-CC-DD` | 4 字节 |
| `AA:BB:CC:DD` | 4 字节 |
| `0xAA 0xBB 0xCC` | 3 字节 |
| `// 注释\nAA BB` | 2 字节 |
| `/* 段注释 */ AA BB` | 2 字节 |

  非法字符（如 `AA ZZ BB`）会拒绝发送并提示格式错误。

- **追加换行** + **换行符模式（CRLF / LF / CR）** — 每次发送自动追加换行符（AT 命令场景常用）
- **定时发送** + **周期 ms** — 周期性自动发送当前内容，最小 10ms；发送失败时（未连接 / 数据格式错误 / 无目标等）自动停止
- **校验**（9 种算法 +「无」）— 发送前在末尾追加校验字节

| 算法 | 字节 | 用途 |
|------|------|------|
| 无 | 0 | 不追加 |
| 和校验 / ADD8 | 1 | 简单累加和 |
| 累加和取反 / ~ADD8 | 1 | 累加和按位取反 |
| 异或 / XOR8 | 1 | 全字节异或 |
| CRC8 | 1 | 多项式 0x07（标准 CCITT）|
| **MOBUS** | 1 | **CRC8 多项式 0x31**，国内嵌入式常用 |
| ModbusCRC16 | 2 | Modbus RTU 标准，小端 |
| CCITT-CRC16 | 2 | CRC-16/CCITT-FALSE，大端 |
| CRC32 | 4 | Ethernet / ZIP 标准 |
| ADD16 | 2 | 16 位累加和 |

**读取文件** — 直接把文件内容塞进发送框（HEX 模式自动转 hex 字符串）

**多条发送** — 发送区「多条发送」按钮，多行数据批量管理，详见 [5.5](#55-多条发送)

**快捷栏（v1.0.2）** — 发送区上方一行直接平铺当前分组里的每条命令为按钮，点一下即发，无需打开弹窗，详见 [5.5](#55-多条发送)

### 5.4 关键字高亮

数据区标题栏 **「关键字高亮」** 按钮打开弹窗，给数据区里命中的关键字上色，一眼定位关心的字段：

- **多条关键字**，每条**独立颜色**
- 着色方式可选 **背景** 或 **文字**
- 可限定范围：**收 / 发 / 收发**
- **区分大小写**子串匹配；自动跳过时间戳，不会误高亮
- 规则**持久化**，下次启动保留

**分组 / 规则集（v1.0.2）**

- 弹窗左侧是**分组列表**，可 **新建** / **双击重命名** / **删除** 分组，把不同场景的关键字归到各自分组
- 数据区标题栏新增**分组下拉**，选哪个分组生效；含 **「（关闭）」** 项可一键停用全部高亮
- 正在弹窗里**编辑的分组**与当前**生效的分组**相互独立，改这个不影响那个

配合数据区标题栏的 **「只显高亮行」** 可切换按钮（开启时高亮），可只保留命中关键字的行、隐藏其余。

### 5.5 多条发送

**分组（v1.0.2）**

**主界面快捷栏（v1.0.2）**

- 一行 = **[多条发送(编辑)]** + **[▶循环]** + **[分组下拉]**，后面平铺**当前分组里每条命令的按钮**

## 6. 实用技巧

- **Modbus 调试**：显示方式选 HEX + HEX 发送 + 时间分包（20ms）+ ModbusCRC16
- **AT 命令调试**：显示方式选文本 + 追加 CRLF + 换行分包（自动）
- **长跑监控**：开实时记录 → 日志文件可后续 Notepad++ / VS Code 打开分析
- **HEX 写注释**：HEX 发送框可写 `// 行注释`、`/* 段注释 */`、`# 行注释`，提交时自动去除
- **拖动布局**：左右 / 上下分割条都可以拖，调成顺手的比例后下次启动保留
- **盯关键帧**：给关键字配高亮 + 开「只显高亮行」，刷屏里也能只盯命中的行；翻历史时滚动锁定不怕被新数据冲走
- **批量指令**：常用的几条指令丢进「多条发送」勾上循环，按每行延时轮发，省得一条条手敲
- **快捷直发**：把常用命令归到一个分组，发送区上方快捷栏一键平铺成按钮，点哪条发哪条，不用开弹窗
- **分场景高亮**：不同协议 / 模块各建一个高亮分组，用数据区的分组下拉随时切换，调试别的设备时选「（关闭）」即可
- **长跑切包**：实时记录选个分包大小（如 10M），日志写满自动切新文件，状态栏随时能看到当前写到哪个文件

## 8. 常见问题

**Q：TCP Server 开始监听失败 / 端口被占用？**
A：该端口被其他程序占用，或需要权限；换个端口或关掉占用程序再试。

**Q：TCP Client 连不上？**
A：检查远程 IP / 端口是否正确、对端是否在监听、防火墙是否放行。

**Q：UDP 点发送提示"无可发送目标"？**
A：没开"指定远程"且还没收到过任何对端数据。开启"指定远程"填好远程地址，或等对端先发一包。

**Q：UDP 组播收不到数据？**
A：确认防火墙放行、收发在同一组播地址和端口、在同一网段 / 网卡。

**Q：定时发送不工作？**
A：周期最小 10ms，且必须保持连接；断开时定时会自动暂停。

**Q：中文显示乱码？**
A：自动模式默认 UTF-8 优先，乱码会自动回退 GBK。如果还是不对，设备可能用其他编码（如 Big5），在"字符编码"下拉里明确指定，或把显示方式切到 HEX / HEX 转储看原始字节。

**Q：HEX 发送报"长度必须为偶数"？**
A：HEX 是按字节解析的，`AA B` 是 3 个 hex 字符无法配对，补成 `AA 0B` 或 `AAB0` 即可。

**Q：日志文件大了会卡吗？**
A：写入是追加模式，几十 MB / 几百 MB 都不会卡。"最大行数"限制只影响**界面显示**的行数，不影响日志写入。

**Q：往上翻历史时新数据会丢吗？**
A：不会。滚动锁定只是把视图定住，数据照常在后台接收。点右下角「↓ 最新」回到底部即可继续自动跟随。

**Q：开了「只显高亮行」却什么都没显示？**
A：说明当前没有命中的行。先在「关键字高亮」里配好关键字，且范围（收 / 发 / 收发）要匹配，命中的行才会留下。
