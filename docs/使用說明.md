## 1. 快速上手

1. 從 [Releases](https://github.com/heropml/SerialTool/releases) 安裝（見 [第 6 節](#6-安裝與系統需求)），桌面雙擊 **CommTool** 圖示啟動
2. 左側「連線設定」裡選**類型**（串口 / RTT / 網路 / Virtual / BLE）→ 填參數，點 **開啟串口 / 連線 / 開啟 / 開始監聽 / Start Virtual**
3. 右側「資料區」即時顯示收發內容，下方「傳送區」輸入要傳送的資料
4. 需要同窗多連線時用「新建會話」開多標籤（串口 / RTT / TCP / UDP / Virtual / BLE 可並發）

空白終端頂部提供「快速開始」：可直接啟動 Virtual 回環、開啟內建範例或繼續最近工程。幀構造器可儲存個人幀範本；錄製回放會索引最近儲存/開啟的 `.ctrec`。遇到問題可用「幫助 → 匯出診斷包」生成脫敏支援包。Webhook 預設只允許公網 HTTPS；僅在目標確為可信區域網路服務時開啟 LAN / HTTP 例外。

## ⭐ CommTool v1.9.0 RTT 與 Linux 升級修復

- **RTT 中斷連線** — 中斷後可繼續操作介面。驅動程式在背景清理，完成後才釋放目前的探針。舊連線排入佇列的狀態與錯誤提示不會影響新連線。
- **Linux 覆蓋升級** — 安裝程式先檢查並暫存新版檔案。失敗時會嘗試還原舊程式、執行階段與啟動入口，並保留使用者設定。若有檔案無法還原，安裝程式會提示備份位置。

## ⭐ CommTool v1.8.9 多探針 RTT

- **同視窗多路 RTT** — 在不同標籤分別選擇不同的 J-Link，相同型號的兩塊目標板也可同時連線。重新展開除錯器下拉清單會更新探針清單。
- **缺少下行緩衝區時保留連線** — 所選通道無法傳送時，CommTool 會提示檢查通道。

## ⭐ CommTool v1.8.8 串口計時、終端輸入與即時日誌

- 終端模式逐鍵傳送，傳送框顯示目前正在輸入的命令。按 Enter 或點「傳送」會送出設定的行結束符號並清空預覽。退格與游標編輯會更新本地回顯，中文輸入法確認的文字也會傳送。
- 同時開啟串口與 RTT 時，每個分頁分別記錄自己的 HEX 或終端文字。開啟「即時記錄」即可選擇檔案。記錄中手動斷線，再次連上會提示選擇新檔案。交握期間已手動選定的檔案會繼續使用。
- 串口日誌、顯示與錄製沿用背景讀取時間。RX 狀態列會顯示讀取區塊數，啟用時間分包或協定組幀後也會顯示對應計數。將滑鼠停在 RX 上可查看位元組速率與區塊速率。20 ms 邊界取決於相鄰讀取的間隔。

## ⭐ CommTool v1.8.7 串口後端與更新憑證

- 串口預設使用獨立執行緒中的 QSerialPort 後端，主視窗和串口橋接共用連線介面。啟動前設定 `COMMTOOL_SERIAL_BACKEND=pyserial` 可切換後端進行對照。
- 20ms 靜默組幀使用讀取時間戳。Parity / Framing / Break 線路錯誤和選配控制線不支援的情況允許資料連線繼續使用。
- macOS 的 Mark / Space，以及 POSIX 的 1.5 停止位會明確拒絕。線上參數被驅動拒絕且成功回復時，會提示原因並還原控制項。回復失敗會清理連線和執行緒。
- 傳送回傳 Qt 接受入列的位元組數，輸出積壓上限為 4MiB。寫入失敗會清空輸出並關閉連線。
- 更新檢查在系統預設信任庫基礎上補充 certifi 根憑證，修復部分打包環境的憑證驗證失敗。
- **記住即時記錄目錄** — 儲存視窗沿用目前設定檔上次成功記錄的目錄，並依目前時間建議新檔名。

## ⭐ CommTool v1.8.6 串口分幀精度最佳化

- 串口背景等待首位元組，合併驅動緩衝區中已到達的尾部資料，以整塊讀取完成時刻記錄時間戳。
- 時間分包顯示與自動應答靜默組幀使用接收執行緒時間戳，介面排隊時仍按接收間隔判斷。常用靜默時間可設為 20ms。
- 補讀期間提前登記接收活動，避免上一幀提前結束；補讀失敗仍交付已讀取的資料，關閉連線時取消阻塞讀取。
- 自動應答靜默組幀每工作階段最多快取 1MiB，超限提示並丟棄整幀，靜默間隔後恢復匹配。時間分包僅控制顯示，自動應答須另設規則靜默時間，gap=0 按接收塊即時匹配。

更早的版本記錄見 [GitHub Releases](https://github.com/heropml/SerialTool/releases)。

## 2. 主要功能

### 2.1 連線設定

左上角「連線設定」卡片，第一行 **「類型」** 下拉在 Windows 提供共 **8** 個選項（macOS/Linux 無 BLE 時為 7 個；新裝預設 **Serial 串口**）：

| 選項 | 說明 |
|------|------|
| **Serial** | 串口（COM 埠）收發 |
| **RTT** | SEGGER J-Link Real-Time Transfer |
| **UDP** | 無連線收發 |
| **UDP Multicast** | UDP 群播 |
| **TCP Server** | 作為伺服器監聽，接受用戶端連入 |
| **TCP Client** | 作為用戶端連向遠端伺服器 |
| **Virtual** | 虛擬連線（無硬體；可回環；用於驗證與 `.ctrec` 回放） |
| **BLE** | Windows 藍牙低功耗主機（UART 風格 Notify/Write；經典 SPP 仍走 Serial） |

下方欄位**隨類型動態顯隱**：

- **Serial（串口）**
  - **串口**（下拉本機串口，旁邊 **⟳** 手動刷新；後台也會定時掃描熱插拔）
  - **鮑率**（可編輯下拉，常用 1200~2000000）
  - **資料位元**（5 / 6 / 7 / 8，預設 8）、**校驗位元**（None / Even / Odd / Mark / Space）、**停止位元**（1 / 1.5 / 2）
  - 點 **「開啟串口」** 連線
- **UDP**
  - **本地IP**（下拉，列出本機網卡 IP，`0.0.0.0` = 所有網卡）
  - **本地埠**
  - **指定遠端**開關 — 關＝回覆最近發來資料的對端；開＝啟用下面的 **遠端IP / 遠端埠**，固定發往該位址
    - **關**模式下每收到一包資料，會把灰顯的「遠端IP / 遠端埠」自動刷成**最近發來方的位址**（讓你看到目前在跟誰通訊、傳送會回覆給誰；對端變化才刷）。收到某方的封包後想固定回它，直接開啟「指定遠端」即預填好該位址
- **UDP Multicast（群播）**
  - **本地IP**（出 / 入網卡，`0.0.0.0` = 預設）
  - **群播位址**（如 `239.0.0.1`，須落在 `224.0.0.0` ~ `239.255.255.255`）
  - **本地埠**
- **TCP Server**
  - **本地IP**、**本地埠** →「開始監聽」
  - 有用戶端連入後出現 **「目標」** 下拉，可選某個用戶端或 **「全部」**（廣播）來傳送
- **TCP Client**
  - **遠端IP**（必填）、**遠端埠**（必填）→「連線」
- **Virtual（虛擬）**
  - 可不接硬體直接啟動；可選 **回環**
  - 用於驗證自動應答 / 腳本 / 序列，以及會話錄製回放時的注入落點
- **RTT（SEGGER J-Link）**
  - 選擇 **晶片**、**除錯器**（自動或序號）、**介面**（SWD/JTAG）、速度（kHz）和通道。自動會優先使用上次成功的探針；明確指定序號絕不自動改選其他探針。
  - 同時使用多把探針時，每個 RTT 標籤選擇不同的除錯器序號。通道號由各塊板的韌體設定，兩塊板的命令終端都設定在通道 0 時，兩個標籤都選 0。取得實際序號後，自動重連會沿用同一把探針。缺少下行緩衝區的通道仍可接收資料。
  - 晶片旁的 **「…」** 開啟完整 J-Link 目錄，支援篩選、排序和回填；側欄故意只保留常用捷徑，仍可自由輸入晶片名。
  - **RTT 位址**支援自動、精確位址，以及 `起點+範圍` / `起點..結束` 的 RAM 搜尋；**連線時重設**為可選項。
  - 需安裝 SEGGER J-Link 驅動。J-Link 已啟動 RTT、但韌體控制區塊尚未出現時會顯示等待提示，而非中斷。
- **BLE（Windows）**
  - 點 **掃描** 會彈出視窗，列出名稱 / 位址 / 廣播 **UUID** / RSSI（含訊號條）/ **TX** / **可連線** / **觀測間隔（估算）** / **廠商**（按位址去重）。該間隔是本機兩次收到掃描回呼的平滑時間差（受 Windows / Bleak 批次處理、掃描回應、丟包影響），**不是**裝置廣播封包裡的真實 Advertising Interval，不能用來判斷周邊廣播週期。**過濾**打開後可勾選規則（預設隱藏無名空包；還可只要有名稱 / 可連線 / UUID / 廠商資料、隱藏過期、只要用過）；關掉則全部顯示。可打開 **RSSI 過濾**，用 −100～−30 dBm 滑條隱藏弱訊號。選取一列看底部廣播明細（類型、Flags、外觀名、廠商名、廣播服務個數、上次連線時間、服務資料、可複製 RAW）。一段時間無廣播的列會變灰。可按名稱 / 位址 / UUID / 廠商搜尋。雙擊或點 **使用此裝置** 填回側欄
  - 再選 **範本**（FFF0 / FFE0 / Nordic UART / Microchip UART / Custom）+ 可編輯的服務 / **寫入（PC→裝置）** / **通知（裝置→PC）** UUID，方向反了可 **對調**。**寫入方式** 預設自動（依特徵屬性選 Write 或 Write Without Response）
  - 點 **「連線」**；連線中顯示「連線中…」，按鈕為中斷（可取消）。狀態列顯示名稱 + 位址 + **MTU**
  - 連上後走既有收發管線（文字/HEX、日誌、`.ctrec`、自動應答、序列、腳本、組幀）。**無 PCAP**；macOS / Linux 會提示不支援
  - 同一裝置不能被兩個工作階段同時開啟；自動重連按已儲存的位址 + UUID，不再掃描，最多 10 次（與串口相同）

**動作按鈕**文案隨類型 + 狀態變化：

- Serial：開啟串口 / 關閉串口
- RTT：連線 / 中斷
- UDP / UDP Multicast：開啟 / 關閉
- TCP Server：開始監聽 / 停止監聽
- TCP Client：連線 / 中斷
- Virtual：Start Virtual / Stop Virtual
- BLE：連線 / 中斷

連線建立後整張卡片**鎖定變灰**；隨協議停用的輸入框也會變灰。

### 2.2 資料接收

收發同框顯示，箭頭區分方向：

| 標記 | 含義 |
|------|------|
| `← 收` | 接收到的資料 |
| `→ 發` | 傳送出去的資料 |

**顯示選項**（資料區卡片）

- **顯示方式** — 文字 / HEX / HEX 轉儲 / 數值（互斥）；收發一致，與「HEX 傳送」無關。轉儲可選列寬；數值可選型別與位元組序
- **自動換行** — 行超長自動換行，關閉後右側捲動條
- **字元編碼** — 選 自動 / UTF-8 / GBK / GB2312 / GB18030 / Big5 / ASCII / Latin-1 共 8 項；影響 RX 解碼 / TX 文字編碼 / 檔案載入
- **顯示時間戳** — 每個新區塊前加 `[2026/06/03 09:48:54 023]`，同時顯示 ← / → 方向箭頭
- **時間分包** + **逾時 ms** — 兩次接收間隔超過設定毫秒就開新行（預設 20ms，適合 Modbus）
- **換行分包** + **換行符模式** — 按 `\r\n` / `\r` / `\n` 切行
  - **自動**：三種風格全識別（Windows + Linux + Mac 相容）
  - **CRLF / LF / CR**：只認指定換行符，嚴格模式
- **即時記錄** — Xshell 風格連續日誌寫到 `.log` 檔案，**顯示什麼寫什麼**（帶時間戳、箭頭、HEX/ASCII）
  - **按檔案大小分包** — 開關旁下拉可選 不分包 / 1M / 2M / 5M / 10M / 20M / 50M / 100M，也可手填自訂（如 `3M`、`500K`）；寫到設定大小自動切到新檔（原名加 `_001`/`_002`…）
- **最大行數** — 顯示行上限，超出自動丟棄最舊的（防止長跑卡頓）；**不影響日誌檔案**
- **只顯高亮行** — 開啟後只保留命中關鍵字高亮規則的行，其餘隱藏；方便在大量資料裡只盯關鍵內容

**捲動鎖定 / 自動跟隨**

- 資料停在底部時自動跟隨最新資料；一旦**往上捲**，畫面就定住不再被新資料頂走，但新資料**照常接收**、不會漏
- 右下角浮動 **「↓ 最新」** 按鈕：點一下回到底部並恢復自動跟隨

**單擊高亮**

- 單擊資料區任一行即高亮整行，方便鎖定一筆關鍵收 / 發；再點一下取消

**字號** — 右上角 `A−` `A+` 微調（7~28pt），適配大螢幕 / 小螢幕

**儲存 / 清空** — 卡片底部按鈕，儲存為 `save_log_YYYYMMDD_HHMMSS.log`

**協議幀解析**（標題列「功能 → 幀解析」）— 預設每個收包當一幀。串口/TCP 黏包、拆包時勾選 **協議幀模式**，按幀頭+長度欄位組完整幀後再解析（波形 HEX / 儀表板 HEX / 結構化記錄共用）。UDP 預設一資料報一幀。顯示區與 `.ctrec` 仍是原始收包。對話框底部有解析計數；「沒有欄位」時可看最近失敗原因。

**右鍵選單** — 在資料區按右鍵彈出 複製 / 全選 / 清空 / 儲存，以及 **轉為文字 / 轉為 HEX**（選區互轉，結果彈窗 + 剪貼簿，上限 64 KiB）；選單文字跟隨程式語言

### 2.3 資料傳送

- **HEX 傳送** — 輸入的 16 進位字串按位元組傳送，下面寫法都識別：

| 寫法 | 解析 |
|------|------|
| `AA BB CC DD` | 4 位元組 |
| `AABBCCDD` | 4 位元組 |
| `AA-BB-CC-DD` | 4 位元組 |
| `AA:BB:CC:DD` | 4 位元組 |
| `0xAA 0xBB 0xCC` | 3 位元組 |
| `// 註解\nAA BB` | 2 位元組 |
| `/* 區塊註解 */ AA BB` | 2 位元組 |

  非法字元（如 `AA ZZ BB`）會拒絕傳送並提示格式錯誤。

- **Ctrl+Enter 傳送** — 普通傳送框 Ctrl+Enter 傳送，Enter 仍換行（終端模式不變，Enter 透傳）
- **追加換行** + **換行符模式（CRLF / LF / CR）** — 每次傳送自動追加換行符（AT 命令場景常用）
- **定時傳送** + **週期 ms** — 週期性自動傳送目前內容，最小 10ms；傳送失敗時（未連線 / 資料格式錯誤 / 無目標等）自動停止
- **校驗**（9 種演算法 +「無」）— 傳送前在末尾追加校驗位元組

| 演算法 | 位元組 | 用途 |
|------|------|------|
| 無 | 0 | 不追加 |
| 和校驗 / ADD8 | 1 | 簡單累加和 |
| 累加和取反 / ~ADD8 | 1 | 累加和按位取反 |
| 異或 / XOR8 | 1 | 全位元組異或 |
| CRC8 | 1 | 多項式 0x07（標準 CCITT）|
| **MOBUS** | 1 | **CRC8 多項式 0x31**，國內嵌入式常用 |
| ModbusCRC16 | 2 | Modbus RTU 標準，小端 |
| CCITT-CRC16 | 2 | CRC-16/CCITT-FALSE，大端 |
| CRC32 | 4 | Ethernet / ZIP 標準 |
| ADD16 | 2 | 16 位元累加和 |

**讀取檔案** — 直接把檔案內容塞進傳送框（HEX 模式自動轉 hex 字串）

**多條發送** — 傳送區「多條發送」按鈕開彈窗，一次管理多條常用資料、可勾選後迴圈輪發，詳見 [2.5 多條發送](#25-多條發送)

### 2.4 關鍵字高亮

資料區標題列 **「關鍵字高亮」** 按鈕開彈窗，按關鍵字替指定的收 / 發內容自動上色：

- **多條關鍵字**，每條可設**獨立顏色**
- 每條可選 **「背景」** 或 **「文字」** 上色方式
- 每條可限定生效**範圍**：收 / 發 / 收發
- 子字串比對，**區分大小寫**；自動跳過時間戳，不會誤把時間戳染色
- 規則**持久化**，下次啟動沿用

**分組／規則集** — 同一批關鍵字可整理成多個分組，按場景隨時切換：

- 彈窗左側為**分組列表**，可**新增** / **重新命名（雙擊）** / **刪除**分組
- 資料區標題列的**分組下拉**選擇哪個分組生效，含 **「（關閉）」** 項一鍵停用全部高亮
- 在彈窗裡**編輯的分組**與目前**生效的分組**相互獨立，編輯時不影響目前顯示

搭配資料區標題列的 **「只顯高亮行」** 可切換按鈕（開啟時高亮），可只保留命中關鍵字的行、隱藏其餘，從大量資料裡快速聚焦關鍵內容。

### 2.5 多條發送

傳送區 **「多條發送」** 按鈕開彈窗，集中管理多條常用資料：

- 每行一條資料，前面帶**核取方塊**
- 每行可**獨立設定** HEX / 換行 / 校驗，並可填 **「名稱」** 與 **「延時（ms）」**
- 勾選多條後 **「迴圈發送」** 按設定間隔依次輪發
- 條目**持久化**，下次啟動沿用

**分組** — 彈窗左側為**分組列表**，可**新增** / **刪除** / **雙擊改名**，把不同場景的常用命令分開管理。

**主介面快捷列** — 不必每次開彈窗，發送區上方一行直接操作：

- 一行 = `[多條發送（編輯）]` `[▶迴圈]` `[分組下拉]` ＋ 該分組每條命令平鋪成按鈕
- 點任一命令按鈕**直接發送**那條
- 按 **`▶迴圈`** 依目前分組各行的 **「延時」** 依次輪發

### 2.6 介面

- **檢查更新** — 點擊後自動從更新來源讀取最新版本，並與目前版本比對：
  - **有新版本** → 對話方塊顯示新版本號、**更新說明** 與 **「下載並更新」** 按鈕。點擊開始下載（帶**進度百分比**）。

  - **已是最新** → 提示目前已是最新版本。

### 2.12 設定自動儲存

- **Modbus 除錯**：顯示方式選 HEX + HEX 傳送 + 時間分包（20ms）+ ModbusCRC16
- **AT 命令除錯**：顯示方式選文字 + 追加 CRLF + 換行分包（自動）

## 5. 常見問題

**Q：TCP Server 開始監聽失敗 / 埠被佔用？**
A：該埠被其他程式佔用，或需要權限；換個埠或關掉佔用程式。

**Q：TCP Client 連不上？**
A：檢查遠端 IP / 埠是否正確、對端是否在監聽、防火牆是否放行。

**Q：UDP 點傳送提示「無可發送目標」？**
A：沒開「指定遠端」且還沒收到任何對端資料；開啟「指定遠端」填好遠端位址，或等對端先發一包。

**Q：UDP 群播收不到資料？**
A：確認防火牆放行、收發在同一群播位址和埠、在同一網段 / 網卡。

**Q：RTT 找不到 J-Link 或控制區塊？**
A：先安裝官方 SEGGER J-Link 驅動，再核對探針、介面、晶片名和速度。「等待控制區塊」表示探針已連上、但韌體尚未初始化 RTT；檢查韌體 RTT 初始化，或按目標提供的位址/範圍填寫。

**Q：定時傳送不運作？**
A：週期最小 10ms，且必須保持連線；中斷時定時會自動暫停。

**Q：中文顯示亂碼？**
A：自動模式預設 UTF-8 優先，亂碼會自動回退 GBK。如果還是不對，裝置可能用其他編碼（如 Big5），在「字元編碼」下拉裡明確指定，或把顯示方式切到 HEX / HEX 轉儲看原始位元組。

**Q：HEX 傳送報「長度必須為偶數」？**
A：HEX 是按位元組解析的，`AA B` 是 3 個 hex 字元無法配對，補成 `AA 0B` 或 `AAB0` 即可。

**Q：日誌檔案大了會卡嗎？**
A：寫入是追加模式，幾十 MB / 幾百 MB 都不會卡。「最大行數」限制只影響**介面顯示**的行數，不影響日誌寫入。

## 6. 安裝與系統需求

可在 [GitHub Release](https://github.com/heropml/SerialTool/releases/tag/comm-v1.9.0) 下載 v1.9.0 安裝包，鏡像附件見 [Gitee Release](https://gitee.com/heropml/SerialTool/releases/tag/comm-v1.9.0)。

### Windows

- 系統：Windows 10 / 11（64 位元）
- 建議：`CommTool_Setup_v1.9.0.exe` — 精靈安裝，可選桌面捷徑；目前使用者安裝無需系統管理員

### macOS

- 僅 **Apple Silicon**（arm64）：從 `comm-v1.9.0` 下載 `CommTool_v1.9.0.dmg`
- 開啟 DMG，把 CommTool 拖進「應用程式」
- 若提示「已損壞，無法打開」（未公證），在終端執行一次：

```bash
xattr -dr com.apple.quarantine /Applications/CommTool.app
```

### Linux

- **x86_64**，glibc ≥ 2.27（Ubuntu 18.04+ / 多數麒麟）。xcb / X11 已打進包，一般不必再 `apt`
- 檔案：`CommTool_Setup_v1.9.0_linux_x86_64.run`

```bash
chmod +x CommTool_Setup_v<version>_linux_x86_64.run
./CommTool_Setup_v<version>_linux_x86_64.run
```

- 預設裝到 `~/.local/opt/CommTool`（**無需 sudo**），並寫入應用程式選單與桌面圖示
- 啟動：選單 / 桌面圖示，或 `~/.local/opt/CommTool/CommTool`（若 `~/.local/bin` 在 PATH 也可直接 `CommTool`）
- 解除安裝：`~/.local/opt/CommTool/uninstall.sh`
- 串口列表為空：把目前使用者加入 `dialout` 組後重新登入：`sudo usermod -aG dialout $USER`

磁碟約 100–200 MB。

使用 RTT 還需安裝官方 SEGGER J-Link 驅動；應用已隨包帶上 Python 封裝。
